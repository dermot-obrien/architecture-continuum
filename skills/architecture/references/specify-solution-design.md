# Specify: template mode for a solution design

The pattern skill ([architecture-pattern](https://github.com/dermot-obrien/architecture-pattern)) ships a solution design template, `assets/templates/solution-design.md`, whose tables carry the fields a design specification needs. A document written from it is translated table by table, by the mapping below, rather than read and interpreted. The rules of the [specify flow](flows/specify.md) still hold: never invent a fact, never record a target-state position, cite each element, connector and scenario back to its row.

## Recognising the template

Use template mode when the document's front matter has `pattern_type: solution-design` (or the repository's own type name for it) and the document has the template's tables, recognised by their headings: Building Blocks, Interfaces, Trust Zones and Data, and at least two of Who Uses It, Where It Sits, Pattern Realisation, Evals, Quality, Failure and Misuse Scenarios, and Operations. A document that has only Building Blocks, Interfaces and Scenarios, such as an architecture pattern or a reference architecture from the same skill, uses those three tables by this mapping and is otherwise read as the specify flow says. Say in the gaps list which mode was used.

## How a cell becomes a field

- A blank cell is a gap: leave the field out and add a question to the gaps list. A cell that holds a value outside the schema's vocabulary is a gap too; never pick the nearest value. `None` is an answer, not a blank: a Departure cell that says `None` means no departure, while a blank one is asked about.
- A vocabulary value is matched ignoring case, with spaces read as hyphens: `Two-way door` is `two-way-door`, `LLM judge` is `llm-judge`, `Partially trusted` is `partially-trusted`, `Yes` and `No` are `true` and `false`.
- An identifier in a table (`TZ-01`, `DS-02`, `IF-03`, `EVAL-01`, `DEC-02`, `FF-01`, and the scenario keys `Q1`, `F1`, `M1`, `S1`) becomes the same identifier in lower case (`tz-01`), because local ids are lower case. A building block takes its whole name in kebab case as its id (`07 ServiceNow knowledge agent` is `servicenow-knowledge-agent`), cited back to its number in a comment; one with a catalogue identifier (`SBB-044 Copilot Studio`) takes its name the same way (`copilot-studio`) and the identifier as `ref`. Wherever a cell names a building block of this design (Realises, Deployed to, a data set's Owner, Grounded on, Provider, Consumer), use its element id; a catalogue identifier that is not a box in this design stays as it is.
- Rows with no identifier of their own take one in row order: constraints `con-01`, assumptions `asm-01`, obligations `obl-01`, open questions `cn-01`, risks `rsk-01`, evidence `ev-01`.
- A name the schema has no field for (an eval's, a fitness function's, an evidence item's title, a functional scenario's sentence) goes in a YAML comment beside the item's id, so the author can find it.
- A cell that holds a list (Alternatives rejected, Options, Concerns) is split at semicolons; a cell with no semicolon is one item.
- `design.source` is written as if the specification sits beside the document: `index.md`. `profiles` follows from the facets: an `ai` facet brings `ai-solution`, an `agent` facet `ai-agent`.
- Keep the document's own words in every prose field.

## The mapping

| Template | Specification |
|---|---|
| Front matter `title` or the H1: identifier and name | `design.id`, `design.title` |
| Front matter `pattern_type`, `pattern_scope`, `version`, `status`, `owner`, `author`, `exposure`, `implements` | `design.type`, `design.scope`, `design.version`, `design.status`, `design.owner`, `design.authors`, `design.exposure`, `design.implements` |
| Front matter `realises`, `flows` | `context.realises`, `context.flows` |
| The document's path | `design.source`; `design.provenance` is `ai-generated`, `ai-raw`, whatever the document's own provenance says |
| Goals and Non-Goals: Kind, Statement, Measure | `drivers.goals` or `drivers.non_goals`: the statement, followed by "measured by" and the measure when there is one |
| Who Uses It | Confirms `design.exposure`; no field of its own. A blank From where is asked in the gaps list |
| Where It Sits: Kind, Identifier | Platform `context.platform`; Bounded context `context.bounded_contexts`; Outcome `context.outcomes`; Capability `context.realises`; Use case `context.serves`; Product `context.products`; Landscape `context.landscape` |
| Stakeholders: Stakeholder, Concerns | `drivers.stakeholders`: `role`, and `concerns` split at semicolons |
| Constraints, Assumptions and Obligations: Kind, Statement, Source, Classification | `drivers.constraints` and `drivers.assumptions` (`id`, `statement`, `source`); `drivers.obligations` (`id`, `source`, `classification`, `statement`) |
| Trust zones: Trust zone, Trust, What it holds | `trust_zones`: `id`, `name`, `trust`, `description` |
| Data sets: Data set, Owner, Classification, Personal data, Residency, Retention, Where it comes from, Used for AI | `data`: `id`, `name`, `owner` (the element id of the building block named), `classification`, `personal`, `residency`, `retention`, `lineage`, `used_for_ai` |
| Building Blocks: Building Block, Role, Kind, Realises, Bounded context, Owner, Trust zone, Deployed to, Source | `elements`: `id`, `name`, `ref`, `responsibilities` (the role), `kind`, `realises`, `part_of`, `owner`, `trust_zone`, `deployed_to`. Source has no field; cite it in the element's comment |
| Pattern Realisation: Pattern building block, Realised here by, Departure, Decision | The blocks in Realised here by go in the named decision's `affects`, whether or not there is a departure. A Departure that is not `None` sets that decision's `departure`: `from` is the pattern building block, `kind` is `time-bound` when the cell gives an end date and `permanent` otherwise, and `expires` and `path_back` come from the cell or are asked for. A blank Pattern building block is a gap |
| Model-Backed Components, first table: Building Block (the element that gets the `ai` facet), Role, Model and provider, Version pinned, Hosting, Input trust, Human oversight, Fallback | The element's `ai`: `role`, `model.name` and `model.provider`, `model.version_pinned`, `model.hosting`, `input_trust`, `human_oversight`, `fallback` |
| Model-Backed Components, second table: Grounded on, Retrieval, Access control, Freshness, Output shown as, Disclosure, Drift monitoring | `ai.grounding.sources`, `.retrieval`, `.access_control` ("the asking user's permissions" is `caller-permission-trimmed`), `.freshness`; `ai.output_handling.rendered_as` (the cell without its words about constraint and validation), with `constrained` and `validated` set where the cell says so, "not constrained" included; `ai.disclosure`; `ai.drift_monitoring` |
| Agents: Started by, Tools and what each can change, Acts as, Limits, Guardrails | The element's `agent`: `initiation`, `tools` (each with its `effect`), `identity.acts_as`, `limits`, `guardrails`. No Agents table and no tools means no `agent` facet |
| Evals: Eval, Building Block (the element whose `ai` facet holds the eval), Kind, Dataset, Metric, Threshold, Positive, False positive, False negative, Must never happen, Gates release, Sample size | `ai.evals`: `id`; `kind` (`LLM judge, calibrated` or `LLM judge, not calibrated` also sets `judge_calibrated`); `dataset`; `metric`; `threshold`; `positive_class`; `errors.false_positive` and `errors.false_negative`, each cell written as "meaning; at most N%. Cost: cost" and split into `meaning`, `max_rate` and `cost`; Must never happen sets `zero_tolerance: true` and adds no error of its own, because the Threshold cell states the zero ("Zero leaks"); `gating`; `sample_size` |
| Interfaces: Interface, Provider, Consumer, Purpose, Style, Protocol, Contract, Authentication, Authorisation, Data carried, Untrusted content, Errors and retry | `connectors`: `id`, `to` (the Provider), `from` (the Consumer, who calls), `description` (the purpose, then errors and retry, then any reason the Untrusted content cell gives), `style`, `protocol`, `contract`, `authentication`, `authorisation`, `data`, `carries_untrusted_content` |
| Quality, Failure and Misuse Scenarios: every column | `scenarios`: `id`, `type`, `name`, `quality_attribute`, `source`, `stimulus`, `environment`, `artefact` (the cell's own words), `response`, `response_measure`, `importance`, `difficulty` |
| Fitness Functions: every column | `fitness_functions`: `id`, `characteristic`, `measure`, `threshold`, `automated`, `runs`, `scenarios` |
| Scenarios: `### S1 <name>`, its sentence, its steps | A `functional` scenario: `id` `s1`, `name`, `use_case` from the use case the sentence names, `steps` with `via` the step's interface and `action`. A step's Actor and Target are where it runs, which the interface already says |
| Controls and Guardrails, Cross-Cutting Concerns | No field. An agent's guardrail belongs in the Agents table; anything else is read as evidence for the criteria that ask about it |
| Operations: Service levels, Observability, Deployment, Recovery, Cost, Support, Transition | `operations.slos` (one per objective the cell names, `alerting: true` where it says alerting, `applies_to` the blocks it names, else asked), `.observability` (`conventions` only when the cell names a convention such as OpenTelemetry; platform telemetry and where it goes stay in a comment, and the missing convention is asked), `.deployment`, `.recovery`, `.cost` (`model` only for a reference to a cost model; what is billed and to whom is `unit_cost`; a cap is `budget`), `.support`, `.transition`; a part a cell does not state is a gap |
| Decisions: Decision (with its status), Chosen, Alternatives rejected, Rationale, Reversibility, Departure | `decisions`: `id`, `title`, `status`, `chosen`, `alternatives`, `rationale`, `reversibility`, `departure` |
| Open Questions: Question, Options, Owner, Needed by | `considerations`: `id`, `question`, `options`, `status: open`, `owner`, `due` |
| Risks and Trade-offs: every column | `risks`: `id`, `statement`, `likelihood`, `impact`, `mitigation`, `owner` |
| Evidence: Evidence, Kind, Date, Design version, Outcome | `evidence`: `id`, `ref` (a link's address; its label goes in a comment), `type`, `date`, `design_version`, `outcome`; an outcome that names decisions, scenarios, elements or evals rather than a result is `covers` |
| Catalogue Mapping | Confirms which elements have no `ref`; no field of its own |

Fields the template has no column for (`design.lifecycle_state`, an element's `technology` and `assessed_by`, a connector's `context_relationship`, a model's card and fallback model, a decision's `technical_debt`, an operations runbook) are left out and asked for in the gaps list, like any other blank.
