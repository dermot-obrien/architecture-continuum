# The schema on the continuum

The front matter schemas in [`standards/schemas/v1.1.0/`](../standards/schemas/v1.1.0/) are the machine form of [the continuum](continuum.md): each kind of artefact is a schema, and each relationship between two kinds is a field that holds the other's identifier. This page draws the schemas as one picture, in the same places the continuum's own picture puts the same things, so the two can be read side by side and should say the same thing.

![The kinds of the front matter schemas and the identifier fields between them, laid out as the continuum is: demand space, solution space and runtime](schema.svg)

## How to read it

Each box with a series (`PL-NNN`, `CAP-NNN` and so on) is a kind of the schemas. The spine of the continuum runs down the middle (landscape, platform, capability, bounded context, ABB, SBB, service, deployment node) with a darker border, the demand-side kinds on the left, and patterns, decisions, contracts and stores on the right. Each line is one or more identifier fields: a relationship is recorded on both sides as a field and its inverse, and the line stands for both, named in the table below. In the SVG, hovering over a line shows its fields.

Two boxes are dashed because they are on the continuum but are not kinds: domain and subdomain is recorded as `subdomain_kind` on the bounded context, and module and component as `module_path` and `packages` on the service. Their dotted lines are not fields. The API box is dashed because the kind is still a placeholder. A field that relates a kind to itself, such as an ABB that requires another ABB, is marked with ↻ in the box rather than drawn as a loop.

Compared with [the continuum picture](continuum.svg), every box keeps its place but three. The continuum's Contracts box is the API placeholder here, moved down beside the service that provides and consumes it, because that is where the schemas record contracts. Consideration and decision record, one box there, are two kinds here, and technical debt, a consequence of a decision, is added below the decision record.

## How it is kept true

The picture is generated by `scripts/generate-schema-diagram.mjs` from the schemas, and so are the tables below. The script reads every field whose values are identifiers and fails when a field has no line, when a line names a field no schema has, when a kind has no box, or when the picture and [`continuum.drawio`](continuum.drawio) differ in a way the script does not explain. CI runs it with `--check`, which also fails when this page or `schema.svg` is out of date. After changing a schema or the continuum picture, run:

```bash
node scripts/generate-schema-diagram.mjs
```

The layout (where each box sits and how each line is routed) is declared in the script, because a picture that can be read needs one. What is drawn is not declared: it is the schemas.
