The assessment model: what reads what, and where findings go

Three schemas and the catalogue they cite. A design is assessed against lenses of criteria; each finding answers one criterion and ends up as a design change, a catalogue artefact or a hand-over.

In a schema today AI facet on an element Catalogue or ontology artefact, outside these files Proposed, not yet in a schema

Design specification

standards/assessment/schemas/design.schema.json
  • One file per design, identified as AP, RA or SD.
  • Elements are continuum kinds; there is no model or agent kind.
  • Connectors carry contracts, authentication and whether content is untrusted.
  • Quality, failure and misuse scenarios need a measurable response.

Lens

standards/assessment/schemas/lens.schema.json
  • core always applies; ai-solution and ai-agent apply by profile.
  • A criterion names the design paths it reads and whether a tool or a reviewer decides it.
  • 92 criteria in draft 0.1.0: 39 tool, 30 both, 23 reviewer. The lens atlas has the current count.

Assessment record

standards/assessment/schemas/assessment.schema.json
  • Pins the design by version and digest, and the lenses by version.
  • Findings use ATAM's types: risk, non-risk, sensitivity point, trade-off point.
  • The verdict pairs an outcome with TOGAF's conformance level.

Proposed after draft 0.1.0, not yet in the schemas

  • tests on a criterion, naming the guardrail or external control it checks, so untested guardrails can be reported.
  • observations on the assessment record, after OSCAL, so evidence is kept apart from the findings that judge it.
  • OSCAL's risk status values on accepted risks, and an export of the record to OSCAL for the security hand-over.
